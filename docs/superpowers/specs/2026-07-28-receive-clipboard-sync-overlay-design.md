# 接收文本、剪贴板确认、同步结果与悬浮窗设计

## 目标

在不改变二维码传输协议的前提下，完善四项交互：隐藏接收文本滚动条、保护文件广播不被剪贴板文本直接打断、用弹窗展示同步结果、暂停广播时保留悬浮窗位置但取消置顶。

## 设计

### 接收文本

- 文本消息区域保持 `max-height` 和 `overflow: auto`。
- 隐藏 WebView2 滚动条，但保留鼠标滚轮、键盘滚动、文本选择和复制能力。

### 文件广播期间的剪贴板文本

- 后端记录当前广播源是否为文件。
- 文件广播期间检测到新文本时，只保存为待确认文本并通知前端，不停止当前文件广播。
- 前端复用应用内确认弹窗；确认后切换为文本广播，取消后继续文件广播。
- 每次待确认文本带递增序号，旧弹窗不得清除或发送更新的待确认文本。

### 同步结果弹窗

- `sync_apply` 成功返回后统一打开结果弹窗。
- 展示应用文件数、删除文件数、校正时间戳数、目标目录和全部不一致项。
- 成功与警告使用不同语义状态；异常列表可滚动且隐藏滚动条。
- 弹窗支持关闭按钮、背景关闭和 `Escape` 关闭。

### 二维码暂停行为

- 手动暂停和自动暂停均保留悬浮窗实例、位置、大小和最后一帧。
- 暂停时取消 `on_top`，允许其他应用覆盖。
- 继续广播时复用原窗口并恢复 `on_top`。
- 仅显式关闭悬浮窗或退出应用时销毁窗口。

## 边界

- 不修改二维码协议、Sender/Receiver 数据格式、文件夹同步算法。
- 不新增依赖，不修改根配置。
- 保持现有深浅色主题、按钮与弹窗风格。

## 验证

- CSS 合同测试验证文本滚动条隐藏且仍可滚动。
- 后端测试覆盖文件广播确认、取消、连续剪贴板事件和文本广播直接热切换。
- UI 合同测试验证同步结果弹窗及悬浮窗暂停行为。
- 运行完整测试、Python 编译、JavaScript 语法检查、PyInstaller 构建和 EXE 启动烟测。
